# Canonical Repository Decision

## Decision

**canonical with remediation**

## Why this repository remains canonical

- The repository identity exactly matches `selfcreation0891-eng/Bridge-Builders-Collective`.
- The commit history consistently develops **Bridge Builders Collective** rather than a different product. (Evidence: 29-commit `origin/main` history)
- Governance, policy, accessibility, trust, and ecosystem-front-door concerns are already concentrated here.
- Replacing this repository would discard intentional naming, history, and early doctrine without solving the underlying implementation gaps.

## Why remediation is required

- There is no actual frontend application root.
- There is no actual Supabase implementation.
- Documentation canon is fragmented across root, `doc/`, `docs/`, `supabase/`, and a malformed `frontend\README.md` file.
- Legal/policy language includes placeholders and unverified operational claims.
- Trust Center, ecosystem navigation, participation pathways, and launch readiness are not implemented.

## Preservation value

High. The repository contains the clearest current record of Bridge Builders Collective identity, governance posture, safety framing, and public-trust intent.

## Migration-cost assessment

Creating a replacement repository would add unnecessary migration cost, fracture history, and likely duplicate the same unfinished documentation layer. Remediation in place is the safer path.

## Required remediation themes

1. reconcile documentation canon and boundaries
2. establish a real application root
3. convert aspirational policy claims into reviewed and implementable commitments
4. define connected-repository boundaries before building cross-ecosystem surfaces
5. complete public-front-door information architecture before activation
