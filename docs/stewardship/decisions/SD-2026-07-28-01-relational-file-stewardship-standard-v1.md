## Decision

The Bridge Builders Relational File Stewardship Protocol, delivered by the founding steward as a written directive on 2026-07-28, is adopted as the canonical **Relational File Stewardship and Self-Audit Standard v1** at `docs/canonical/RELATIONAL_FILE_STEWARDSHIP_STANDARD.md`. It operates as a subordinate canonical governance standard at authority level 5, alongside the canonical vocabulary and public claims standard, and is the authoritative operating standard for classifying, relating, reviewing, creating, moving, merging, archiving, deprecating, and completing all Bridge Builders files and artifacts.

The directive's operative instruction: "Turn this protocol into the canonical Bridge Builders Relational File Stewardship and Self-Audit Standard. Place it inside the canonical Bridge-Builders-Collective repository in the governance documentation area. Treat it as the authoritative operating standard…"

## Rationale

The ecosystem's governance canon (Constitution, authority order, registry standard, claims standard) governed public truth and environment status but had no ecosystem-wide standard for artifact placement, relational classification, duplicate handling, completion status, or conversation-to-system conversion. The directive supplies that missing layer and instructs its canonization.

## What this decision does not do

- It does not add, rename, or re-status any entry in the canonical ecosystem registry. Entities named in the source protocol that are not registered (see conflict C-017) remain unregistered, with their artifacts classified Proposed.
- It does not confirm a canonical domain (conflict C-018; `docs/DOMAIN_ACTIVATION_CHECKLIST.md` step 1 remains open).
- It does not add vocabulary entries; proposed terms route through `CHANGE_AUTHORITY.md`.
- It does not appoint anyone, expand any steward post's authority, or alter SOPHIA's advisory-only boundary.
- It does not adopt any independent system (CloseOne Flow remains separate).

## Conflicts reconciled at adoption

Recorded in `docs/CANONICAL_CONFLICT_REGISTER.md` as C-015 through C-018. Where the source protocol's wording differed from existing canon (project naming, registry deference, domain rule), the canonical standard defers to the higher authority and the register records the disposition.
